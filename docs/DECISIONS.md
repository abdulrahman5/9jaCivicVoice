# Decisions log

Changes made while building that differ from the architecture doc (19 Oct 2026). Newest first.

| Date | Decision | Why | Update the architecture doc? |
| --- | --- | --- | --- |
| 2026-10-20 | Police patterns are published for completed months only (Lagos time, plus 48 hours), with counts as bands (3–5, 6–10, 11–25, 26+) computed inside the vault. The civic side keeps the first copy of each month. Monthly forwarding totals per city and recipient are published exactly and refreshed nightly. The bridge's vault secret is now `civic_rest_url` (the REST base URL), replacing `civic_ingest_url`. | Product decision: a changing daily count could date an individual report. Forwarding totals describe institutions, and late acknowledgements should count. | Yes: Data architecture (police aggregates) |
| 2026-10-20 | Forwarding packs are copied and sent by hand. The console never builds a `wa.me` or similar link with the pack in the URL; phone and email contacts link only to the number or address. Our reference is `CV-` plus the first 8 hex digits of the report id. | A URL carrying the pack would leave report content in browser history and in the messaging service's web logs, outside the chat itself. The short reference lets the CRU and PSC quote it back without saying anything about the reporter. | No |
| 2026-10-20 | Police console: every render of a report page logs a `read` (including the re-render after an action), so queue links don't prefetch and the wellbeing prompt counts distinct reports. Non-police staff get "no access" on the queue and a 404 on report URLs. | The access log should over-record rather than miss a view, and a prefetch must never log a read nobody made. A 404 doesn't confirm that a report exists. | No |
| 2026-10-20 | The police pages load Cloudflare Turnstile, the only outside script, and only via the page's own JS (CSP allows `challenges.cloudflare.com` for scripts and frames). The Worker refuses police submissions and messages when Turnstile isn't configured or can't be reached, and never sends the visitor's IP to it. | Bot protection is needed on an anonymous form, and Turnstile comes from Cloudflare, which already hosts the Worker, so no new party sees reporters. | Yes: Police vault controls ("no third-party scripts") |
| 2026-10-20 | Police forwards are one row per recipient (`police.forwards`), so CRU and PSC outcomes are tracked separately. Rejected police reports get `closed_at`, so the 12-month purge covers them. | The spec tracks outcomes per recipient, and without `closed_at`, rejected reports would never be purged. | No |
| 2026-10-20 | Police reporting v1 (docs/POLICE.md): an anonymous message box tied to the status code; commendations for good conduct; forwarding to the CRU and PSC only; patterns only, no live alerts. | Product decisions from the police-feature brainstorm. | Yes: PRD F5 |
| 2026-10-20 | Status codes get a deterministic `status_lookup` (HMAC with a Worker secret) next to the salted hash, and grow from 4 to 6 words. | With a per-report salt, a code can't be matched to its report without re-hashing against every row. Codes now unlock a conversation, so 32 bits is too few. | Yes: Police vault controls |
| 2026-10-20 | Police reports are marked "consistent", never "verified". | We can't prove an anonymous report true; the label shouldn't claim we did. | No |
| 2026-10-20 | Turnstile fails closed in production: with no secret, or if Cloudflare can't be reached, reports are refused. The report form renders the widget whenever a site key is set. | Before this, the form never sent a token, so every production submission would have failed. Failing closed means a misconfigured deployment can't quietly accept bot traffic. | No |
| 2026-10-20 | Previews run on Vercel's GitHub integration, plus a manual `Preview database` workflow that migrates and seeds a Supabase preview project (docs/PREVIEW.md). `NEXT_PUBLIC_SITE_URL` is optional on Vercel, and the police form URL is optional ("Coming soon"). | The build session can't reach Vercel or Supabase, and the repo is public. GitHub-hosted runners can reach them, and secrets stay in GitHub and Vercel. | Yes: Environments and CI/CD |
| 2026-10-20 | In the Supabase config, `[auth.email] enable_signup` stays `true`; public sign-up is blocked by `[auth] enable_signup = false`. | Setting the email one to `false` disables email login entirely, which locked staff out. Verified locally that `/auth/v1/signup` still returns `signup_disabled`. | No |
| 2026-10-20 | Agency links are created from the issue page after routing ("Create agency link"), not returned by the route action. Moderators email the link themselves until the `forward_agency` email job exists. | After routing, the issue is no longer editable, so the page re-renders without the routing form, and a link shown there was lost. A panel that stays on screen is reliable. | No |
| 2026-10-20 | Staff accounts are created with a script (`staff:create`) that prints a one-time password; TOTP setup is forced at first sign-in. | There's no public sign-up. Password change at first sign-in is still to do. | No |
| 2026-10-19 | Phone numbers are stored **encrypted** (AES-256-GCM, key outside the database) as well as hashed, and both are cleared 90 days after the issue closes. | The doc said numbers exist "only as a salted hash", but a hash can't be messaged: status updates on WhatsApp need the number. Encryption with an external key keeps a database dump useless on its own. | Yes: Data architecture, Security sections |
| 2026-10-19 | Queue workers run as a Next.js route (`POST /api/jobs/run`), called by pg_cron via pg_net, instead of Supabase Edge Functions. | The bot state machine, validation and i18n are TypeScript workspace packages. Running workers in the same app reuses them directly, rather than duplicating them for Deno. pgmq, pg_cron and retries are unchanged. Revisit if jobs outgrow Vercel's function limits. | Yes: D4, Async processing |
| 2026-10-19 | The police database uses the schema name `police`, not `vault`. | Every Supabase project already has a `vault` schema (its built-in secrets store), and the bridge jobs use it. | Yes: Data architecture |
| 2026-10-19 | Database projects live in `db/civic` and `db/vault`, not `supabase/civic`. | The Supabase CLI expects a `supabase/` folder inside each workdir. | Yes: Codebase structure |
| 2026-10-19 | WhatsApp reports get subcategory `other`; a typed (not shared) location is stored as text, with `location` null until a moderator places it. The bot asks for the city only when no pin is shared. | Keeps the WhatsApp conversation to four short steps. | No |
| 2026-10-19 | Status codes for police reports are hashed with PBKDF2-SHA256 (100k iterations), not Argon2id. | Argon2 needs WASM in Workers; PBKDF2 is in WebCrypto. Codes are rate-limited at the edge. **Move to Argon2id before launch.** | No (tracked in README "Next up") |
| 2026-10-19 | Fonts use the system stack; Public Sans will be self-hosted via `next/font/local`. | Loading Google Fonts would send every visitor's IP to Google. | No |
